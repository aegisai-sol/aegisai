AegisAI Whitepaper — Proof-of-Verification Reservoir (PoV-R)

Version 0.3 · 31 October 2026 · Status: token live on Solana mainnet (CA GhSiU95vtKwn7FBAW1u5krxYP2PnpFPotb1LJFZkbzhW), mining claims in beta. Audit: not yet — planned (no third-party audit has been completed). Not financial advice.

Abstract

AegisAI is a verification network for AI output. Instead of building another large language model, AegisAI splits AI answers into small, checkable micro-claims, has many low-power nodes verify them, aggregates the votes with commit–reveal consensus, and issues a receipt that can be anchored on Solana. The economic layer, the Reservoir, rewards correct verification with Proof Credits that convert to AGIS only against real, paid verification fees.

1. Problem

  1. AI hallucinations. LLMs state wrong facts, sums and fake citations with confidence. Businesses using AI need checked output.
  2. Verification is mis-priced. Most checks (a date, a sum, a quote, a URL) are tiny. Sending each one to a frontier model or a human is slow and costly.
  3. No portable proof. When an answer was checked, there is usually no receipt a third party can audit.

2. Solution overview

PoV-R = Proof-of-Verification + Reservoir. - PoV is the protocol: decompose → assign → verify → commit–reveal → aggregate → attest. - Reservoir is the economics: hard-capped supply, Proof Credits for correct votes, conversion capped by real fee revenue.

3. The Proof-of-Verification round

  1. Decompose — AI text is split into micro-claims (e.g. "17 × 23 = 391", "Source X says Y").
  2. Assign — each claim goes to k random nodes (k = 5–15), weighted by reputation (and stake later), across device classes.
  3. Verify — nodes run deterministic methods: arithmetic/rules, Proof-of-Source, small local models later. Output: TRUE / FALSE / UNSURE + confidence.
  4. Commit–reveal — nodes commit H(vote‖salt‖node‖task) then reveal, preventing copy-voting.
  5. Aggregate — weighted ≥ 2/3 supermajority finalizes; otherwise escalate.
  6. Attest — batch Merkle root of verdicts to Solana (Memo first, dedicated program later). Each claim gets a receipt ID.

4. Verification methods

  • Arithmetic & rules — deterministic checks of numbers, units, dates.
  • Proof-of-Source — fetch the cited URL and check whether the quoted text actually exists on the page (normalized fingerprint). Catches fabricated citations — one of the most common AI failures.
  • Calibration canaries — known-answer tasks injected at random to detect lazy or dishonest nodes.
  • Small models (planned) — quantized NLI/fact classifiers (< 1 GB, ONNX/WebGPU) for claims rules can't settle.

5. Reservoir & Proof Credits

  • Max supply (hybrid): 10,000,000,000 AGIS — 1B team (2MzLPXNvkU2VsezPFgdM6SGFHzddGURMguAFAFwKkoXM), 500M ecosystem (9DmwoF1qJ8fASDasjkE2jacrEAWuRwUnDWwJ41eQgKan), remainder emitted only via mining. Mint authority is held for mining emission (not yet revoked); freeze authority: none.
  • Nodes earn Proof Credits (off-chain ledger first, Solana later) for votes that match the final verdict and pass canaries.
  • Credits convert to AGIS only against paid verification fees: at most 70% of fees per epoch and at most 0.5% of Reservoir per epoch. No fees → no emission.
  • This ties token issuance to real usage rather than inflation.

6. Role of the AGIS token

AGIS is integral to PoV-R: it pays miners/verifiers, is used for verification fees, and later for node stake/slashing. Token is minted on Solana mainnet; trading/LP and a third-party audit are next steps.

7. AI — but not another LLM

AegisAI does not compete with OpenAI, xAI or others. Any model's output (theirs, or a future AegisAI helper) can pass through PoV. AegisAI is the trust layer: AI produces, PoV verifies, receipts prove.

8. Architecture

Requesters → Coordinator API (decomposer, task queue, assigner, commit/reveal store, aggregator, credits ledger) → nodes (browser PWA, Python, Docker later) → batched attestation on Solana. Key endpoints: POST /v1/verify, GET /v1/receipts/{id}, POST /v1/nodes/register, GET /v1/tasks/next, commit/reveal. Nodes sign with their wallet (ed25519); private keys never leave the device.

9. Security model

Threat Mitigation
Copy-voting Commit–reveal, salted task variants
Collusion Random assignment, cross-device quorums, correlation detection
Sybil Reputation warm-up, rate limits, stake later, optional device attestation
Always-TRUE free-riding Calibration canaries
Coordinator trust Phase 1 centralized but publishes commitments; later multi-coordinator + on-chain settlement

10. Future vertical: RWA Doc Check

Tokenized real-world assets rely on documents (NAV reports, filings, insurance, audits). AI summaries of these are increasingly used — and can be wrong. RWA Doc Check applies Proof-of-Source to them: "NAV is X" or "the asset is insured" is checked against the actual public filing, with a receipt. AegisAI will not tokenize assets or act as a price oracle; it verifies claims about them. Planned after the core Verify product (6–12 months).

10b. Privacy Seal, recovery & GDPR (honest)

What a seal is. For each file the browser computes a SHA-256 fingerprint. In private mode the file (with its name and type) is encrypted with AES-256-GCM in the browser; the key (agis1:…) is shown once to the uploader and is never sent to us. The network stores the fingerprint, minimal metadata and (optionally, <3 MB) the ciphertext. Miners check integrity without decrypting and vote; the result is anchored on Solana as a Memo receipt AEGIS/rwa/v1|id|fingerprint|status. A Seal ID is a unique, permanent identifier — no per-document NFT is needed (optional NFT certificates later).

Recovery (lost phone / lost key). If you still have the same file (email, cloud, USB), re-select it on Verify / Prove: the fingerprint is recomputed and matched via GET /api/rwa/by-fingerprint/:sha256 and the on-chain receipt. No key needed for proof. A public link proof.html?id=… shows status + Solscan only. The key is only needed to view the encrypted bytes; if both file and key are lost, the content cannot be recovered by anyone — by design. A fresh scan of a paper original is a different file and gets a different fingerprint.

Lost phone AND lost key (wallet key-wrap, Wave A2). Optionally (default when Phantom is connected) the AES key is wrapped with a key derived via HKDF-SHA256 from your Phantom signature of AEGIS/rwa-keywrap/v1|wallet|sealId|fp. Only the wrapped blob is stored (fields keyWrap, wrapWallet, wrapAlg); the signature never leaves your browser. On any new device: connect the same wallet → sign → unwrap → decrypt locally. We never custody keys; only that wallet can unwrap. If the wallet seed is lost too, planned social recovery (2-of-3 guardians) — not yet built. Never sign AEGIS key-wrap messages on other sites.

What it proves / does not. Proves: this exact file existed at time T and is unchanged since. Does not prove: who issued it or that its claims are true — that requires the issuer, a registry or a signature.

GDPR stance. The uploader is the data controller. We store no plaintext and hold no keys. On-chain data is a hash and status only (no names, IDs or content). Off-chain ciphertext copies can be deleted on request; the on-chain hash remains but reveals nothing on its own. Do not upload third-party personal data without a lawful basis. Formal terms, DPA and an external audit are still to do.

What this is / What it is not

AGIS seals put a SHA-256 fingerprint, seal time, and miner verdict into a Solana Memo. That is an immutable public timestamp of file integrity. Useful for invoices, photos, CSV exports, lab exports — anyone can re-hash and compare.

Not claimed: EU eIDAS qualified electronic seal, US notary public, court evidence by default, or ownership of the real-world asset itself. Tokenization of houses is out of scope for v1.

AGIS is an SPL token on Solana L1. It is not a Layer-2 or Layer-3 chain.
